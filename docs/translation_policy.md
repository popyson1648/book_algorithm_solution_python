## 1. まず観測可能な動作と学習目的を決める

入力形式・出力形式・計算対象・副作用・前提条件を確認してから移植する。教材では結果だけでなく、状態の持ち方、ループの順序、再帰の呼び出し順、計算量も保存対象とする。

この本は全探索、再帰、DP、二分探索、貪欲法からデータ構造・グラフへ進む構成である。そこで線形探索を `in` や `min()` へ、自作ソートを `sorted()` へ、メモ化配列をデコレータへ一律に置換しない。一方、他のアルゴリズムで単なる道具として使う標準コンテナは対応するPython標準ライブラリに移す。

根拠となる構成：[出版社の目次](https://www.kspub.co.jp/book/detail/5128442.html)、[著者のコード一覧](https://github.com/drken1215/book_algorithm_solution/blob/bf4af1b13b6fb1f58b8a921ab319096422f064d6/codes/README.md)。節の対応は公開目次・コード一覧・解答・正誤表から照合しており、書籍本文全体を閲覧したものではない。番号を厳密に特定しにくい例は章名または節の範囲で示す。

## 2. 構文より先に言語の意味の違いを確認する

| 項目 | 意味の違い | 本移植での扱い |
| --- | --- | --- |
| 整数除算 | C++の整数除算は0方向へ切り捨て。Pythonの `//` は負の無限大方向へ切り下げ | 添字・非負量では `//`。除算対象の符号を確認し、`int(a / b)` による浮動小数点経由の変換はしない |
| 整数の大きさ | Pythonの整数は任意精度。C++の固定幅整数と異なる | 本来の整数演算を保ち、オーバーフローを模倣しない。巨大整数では演算時間も増えると明記 |
| 参照引数 | Pythonで関数内の名前へ代入しても呼び出し元の整数変数は変わらない | `chmin` は新しい値、必要なら更新フラグも返す。配列要素への緩和は直接代入 |
| 配列の複製 | `b = a` は同じリストを参照する | ソート前のコピーには `sorted(a)`、二次元配列には内包表記を使用 |
| 多次元配列 | `[[0] * w] * h` は同じ行を共有する | `[[0] * w for _ in range(h)]` を使用 |
| 添字 | Pythonの負の添字は末尾から参照する | 部分和DPの `w < 0` や `j >= a[i]` を明示。原文の未定義動作を偶然の正常値へ変えない |
| ノード参照 | Pythonのオブジェクト参照と自動メモリ管理を使う | ノード同一性には `is`。不要なリンクを切り、`delete` の機械的な模倣はしない |
| デフォルト引数 | Pythonでは関数定義時に評価される | 可変の番兵は `p=None` とし、呼び出し時に現在の番兵を選ぶ |
| 真偽値・表示 | C++の通常の `cout` はboolを0/1で表示する | Union-Findのデモは `int(bool値)` を出力。Yes/No表記も維持 |
| 浮動小数点表示 | C++の標準出力の既定有効桁数とPythonの表示は異なる | 距離と逆ポーランド記法のCLIでは `.6g` を使用 |
| 文字列 | C++の `string` の添字はバイト、Pythonの `str` はUnicodeコードポイント | 元問題のASCII入力で意味を合わせる。編集距離の関数を日本語に使うとコードポイント単位になる |

一次資料：[C++標準ドラフトの除算規則](https://eel.is/c++draft/expr.mul)、[Python数値型](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex)、[Python代入規則](https://docs.python.org/3/reference/simple_stmts.html#assignment-statements)、[Python FAQ：参照・多次元配列・整数除算](https://docs.python.org/3/faq/programming.html)。

## 3. データ構造の計算量を合わせる

- BFSのキューは `collections.deque` を使う。`list.pop(0)` の要素移動を混ぜない。
- `std::lower_bound` は `bisect_left` に対応させる。探索位置が配列長と等しい場合を明示的に扱う。`bisect` で探したあとにリストへ挿入する操作はO(N)なので、探索と挿入のコストを混同しない。
- 最小優先度キューは `heapq` を使う。第10章の最大ヒープそのものの実装は自作のまま残す。
- 区間和をDPの最内側で再計算しない。累積和の差を使い、O(N³)がO(N⁴)にならないようにする。
- 二次元・三次元DPは説明の状態定義を保つ。ローリング配列への最適化は行わず、領域計算量を明記する。

一次資料：[deque](https://docs.python.org/3/library/collections.html#collections.deque)、[bisectの性能上の注意](https://docs.python.org/3/library/bisect.html#performance-notes)、[heapq](https://docs.python.org/3/library/heapq.html)。

## 5. 正常系の差分テストと、独立した正しさの検証を組み合わせる

同じ入力をC++版とPython版で実行し、出力を比較する。これだけでは原文由来の不具合を検出できないため、別の方法で答えを求めるテストも用意する。

- 部分和・ナップサック・区間選択・木の独立集合：小規模な全列挙。
- 最大流：すべてのs-tカットの容量の最小値と比較。
- 最小全域木：すべての全域木を列挙して最小値や必須辺を確認。
- 最短路：小さなDAGの全パスを列挙。
- ソート・選択：標準ソートの結果と比較。
- 連結リスト・ヒープ・Union-Find・残余グラフ：構造の不変条件を確認。

乱数はシードを固定して再現可能にする。元コードが未定義動作する入力は差分比較の正解に使わず、Python側の回帰テストで検証する。差分テストの有用性はコンパイラ研究でも実証されているが、本移植での正しさは実際のテスト範囲に限定される。[Microsoft Researchの差分テスト研究](https://www.microsoft.com/en-us/research/publication/randomized-stress-testing-of-link-time-optimizers/)、[unittest公式文書](https://docs.python.org/3/library/unittest.html)。

## 6. 再帰深度と性能の限界を明示する

再帰を学ぶコードは再帰を残す。無制限に `sys.setrecursionlimit()` を大きくする設定は加えない。深い再帰への実用的な対応では、入力制約と実行環境を確認し、明示的スタックや反復DPを検討する必要がある。既定の再帰上限を超える入力は今回の再帰版の対応範囲外である。[Pythonの再帰上限](https://docs.python.org/3/library/sys.html#sys.setrecursionlimit)。

計算量の表記は原則として算術・比較を定数時間とする本書のモデルに合わせる。任意精度整数のビット長、文字列の長さ、Pythonオブジェクトのメモリ消費は実行時間・使用メモリに別途影響する。
